      02 / Understand the boundary

      Permission is one question.
      Selection is another.

      Interactive Demonstration of
      Governed Retained-State Selection

      01

      The host sets the boundary.

      The present condition and host rules determine which actions are permitted. That candidate set stays fixed in each comparison.

      02

      History becomes eligible evidence.

      Relevant previous events may influence which permitted action wins. Retained history does not grant new permissions.

      03

      The selection can be inspected.

      Compare against the influence-disabled reference condition, inspect the Decision Record, then replay the same fixture result.

      What CAAI did not do +
      • It did not invent new candidate actions.
      • It did not expand the host's permitted-action boundary.
      • It did not retrain the underlying model.
      • It did not treat retained history as automatic authority.
      • It did not require an external model call to perform this demonstration selection.
      • It did not expose proprietary scoring implementation.

      About the demonstration

      A clear view.
      A defined scope.

      Decision Lab is a buyer-safe interactive demonstration of the CAAI selection boundary. It uses controlled deterministic demonstration cases and does not execute or disclose the proprietary Core Gold runtime, private scoring implementation, thresholds or protected schemas.

      The demonstrator illustrates product behaviour and evaluation concepts. Buyer-specific technical evaluation is performed separately under an agreed scope.

      Decision Lab uses controlled deterministic demonstration cases to explain the CAAI selection boundary. It is not a Core Gold execution environment and should not be treated as runtime evidence.

      No analytics. No cookies. No telemetry. All demonstration selections run locally in your browser.
